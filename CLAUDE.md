# Тёмный прилавок

Пиксельный киберпанк-симулятор лавки на космической станции. Это личный проект, вдохновлённый Probably Stolen. В планах своё лицо: сеттинг, название, крючок.
Игрок сидит за прилавком и делает пять вещей:
- зовёт клиентов;
- осматривает товар;
- торгуется;
- чинит и собирает вещи;
- вечером копает на свалке.

Отец задолжал ростовщику Гробову 20 000 кр. (временный баланс 17.11, `DEBT` в `data.ts`). Раз в неделю Гробов приходит за платежом (400, 550, 700…), платёж уменьшает долг; можно вносить досрочно. Последний шаттл со станции — день 60, место на нём Гробов продаёт только при нулевом долге. Концовки: «Улетел» (место куплено), «Остался на станции», выселение.

Режимы: «Начало конца» (`story`, всё выше), «Без таймера» (`calm`: долг и платежи без шаттла, при нулевом долге — «Долг закрыт» и лавка дальше без платежей), «Своя лавка» (`sandbox`, заготовка, закрыт до Патча B1). Первый запуск — экран выбора режима; дальше игра сразу продолжает последний режим.

Владелец — джун фуллстак, мечтает о геймдеве. Объясняй решения коротко и по-русски: что сделал и зачем. Выбирай инструмент, который подходит задаче, а не «лишь бы работало».

## Стек
- **Vite + TypeScript** (strict), без UI-фреймворков. Интерфейс — HTML/CSS, сцена — `<canvas>`.
- **Vitest** для чистой игровой логики.
- **vite-plugin-pwa** (Workbox) для манифеста и service worker. Ручной `sw.js` не пишем.
- Деплой: GitHub Actions → GitHub Pages. `base: '/dark-counter/'` в `vite.config.ts`.
- Графика: canvas 160×100 логических пикселей, рисуем прямоугольниками: `fillRect(x,y,w,h,color)`, спрайты — списки `[x, y, w, h, color]` для `fillRects()`. Спрайты-картинки только после отдельного решения (тогда, возможно, Phaser для сцены).
- Звук: Web Audio API, генеративный лофи. По умолчанию включён и стартует на первом касании игрока (браузеры не дают звуку стартовать без жеста). «Выкл» в меню запоминается в `localStorage` (`dark-counter-music`), не в сейве. Звуки свалки (раскопка, находки, шум, дрон, «домой») — тоже генеративные, со своим пунктом меню «Звуки: вкл/выкл» (`dark-counter-sfx`), тише музыки.
- Шрифты: **Public Pixel** (CC0) — локальный файл в `public/fonts/`, в прекэше PWA; **IBM Plex Mono** — Google Fonts, офлайн из кэша Workbox `google-fonts` (кириллица 400/500/600 подгружается при старте в `main.ts`). Фолбэки только моноширинные.

## Команды
- `npm run dev` — разработка с hot reload.
- `npm run build` — продакшн-сборка в `dist/`.
- `npm run preview` — проверка сборки локально, в том числе PWA и офлайн.
- `npm test` — Vitest.
- `npm run typecheck` — `tsc --noEmit` (в том числе `tests/sim`).
- `npm run sim -- --seeds 1000 --strategy careful` — бот баланса: доли концовок, день закрытия долга, деньги по неделям (`tests/sim/README.md`); `npm run sim:grid` — подбор чисел `DEBT` по сетке.

## Структура
- `index.html` — разметка, подключает `src/main.ts`.
- `src/main.ts` — инициализация: загрузка сейва, связка модулей, рендер, цикл анимации, регистрация service worker (`registerSW`: новая сборка сразу берёт управление — `skipWaiting`/`clientsClaim` в `vite.config.ts` — и страница перезагружается на неё; при возврате PWA на экран — проверка обновления).
- `src/types.ts` — `GameState`, `Item`, `ItemType`, `Customer` (размеченное объединение по `kind`: `'sell' | 'buy' | 'rent'`). Короткие поля сейва описаны с комментариями.
- `src/data.ts` — товары (`ITEM_TYPES`), рецепты (`RECIPES`), имена, реплики, все балансовые числа (`DEBT`, `RENT`, `HAGGLE`, свалка `JUNK` и `DIG_ODDS`, день: `CLOCK`, неделя `CUSTOMERS_BY_WEEKDAY` и `WEEKDAY_REASONS`, `CUSTOMER_FLOW`, доля покупателей от склада `BUYER_FLOW`/`buyerShare`…), режимы и ключи слотов (`MODES`, `SAVE_KEYS`, `PROFILE_KEY`), строки RU/EN: HUD и меню (`HUD_TEXT`), режимы (`MODE_TEXT`), долг и шаттл (`DEBT_TEXT`), концовки (`ENDING_TEXT`), свалка (`JUNK_TEXT`), день: утреннее окно, причины, чип (`DAY_TEXT`), утренние расходы (`EXPENSES`, `EXPENSE_TEXT`), окно сохранения (`SAVE_TEXT`). Плейсхолдеры `{name}` в строках заполняет `fill()` из `util.ts`. Новый контент добавляется здесь.
- `src/state.ts` — `state` (сейв), `ui` и `actor` (состояние экрана, не сохраняются), `createGame(mode, rng)` (чистая) и `newGame(mode)` (делает её текущей игрой), `createItem(state, type, overrides, rng)`, `addLog(state, text)`, `findItem(state, uid)`, слоты режимов (`saveGame`, `loadGame(mode)`, `readSlot`, `persistence`), `migrate`, `saveSnapshot` (в сейв — последние `SAVE_LOG_LINES` строк ленты), коды: `exportSaveCode`/`importSaveCode` (асинхронные, `DC2:`, фолбэк `DC1:`), `exportSave`/`importSave` (`DC1:`).
- `src/profile.ts` — профиль игрока (`dark-counter-profile`): виденные концовки по режимам, открытые режимы, последний режим. Не сейв: «Новая игра» и коды его не трогают. Чистые функции над `KeyValueStore`.
- `src/economy.ts` — торг (`sellerAcceptChance`/`buyerAcceptChance`, `perceivedChance`), долг: еженедельный платёж и залог (`payRent`, `planCollateral`), досрочный взнос (`payEarly`), место на шаттле (`seatPrice`, `buySeat`), концовки (`endGame`), свалка v2 (`goToJunkyard`, `dig` → `DigResult`, шум `noiseLevel`, `droneChance`, глубина `rareChance`, `digBonus` — точка расширения),  верстак (`useWorkbench`), сборка (`craft`), ночь (`sleepUntilMorning` → `MorningReport`: события и утренние расходы `payExpenses`; `expensesToday` — точка расширения для событий). **Чистые функции без DOM и без глобалов:** `state` и `rng` — параметры (`offerToSeller(state, price, rng)`), экран (выбор вещи, вкладка, фигура на сцене) не трогают — возвращают результат (`callNextCustomer` → пришёл ли кто-то, `offerToSeller`/`craft` → новая вещь, `inspect` → был ли осмотр).
- `src/day.ts` — день: неделя станции (`weekdayOf`, день 7 — день платежа), клиенты дня с причинами (`customersToday` → `{ count, reasons }`), игровые часы (`clockOf`, `openingHour`, `formatHour`): смена 08:00–19:00 делится на клиентов дня, вечер 19:00–24:00 (`EVENING_HOURS` = 5, выводится из `CLOCK`), раскопки за полночь (`late`) сдвигают открытие на 2 ч и забирают клиента. Чистые функции над переданным `GameState`, без своего состояния; число клиентов фиксируется утром в `cn`.
- `src/appearance.ts` — внешность клиента по сиду (`appearanceFor`). Чистая функция: её используют и `economy` (имя человека или робота), и `scene` (отрисовка).
- `src/scene.ts` — canvas: лавка, свалка (одна куча `HEAP` худеет по стадиям, лопата `playDigFx`, сторожевой дрон от шума), спрайты клиентов и товаров (`ITEM_SPRITES`), анимации, `startScene`.
- `src/ui.ts` — HUD, вкладки, панели, модалки, нижняя строка статов, меню ☰ (шторка снизу: сверху название режима, «Долг», «Режимы», «Музыка: вкл/выкл», «Звуки: вкл/выкл», «Сохранение», «Новая игра» → экран режимов), экран режимов и запуск (`startGame`), таблица обработчиков `ACTIONS` (кнопки несут `data-a`).
- `src/window.ts` — компонент окна (V2.2): один API, два вида — мини-окно сбоку от сцены при мыши (`float`, не заходит на зону клиента `CUSTOMER_ZONE`) и шторка над полосой действий при пальце (`sheet`); вид по `matchMedia('(pointer: coarse)')`, меняется на лету. `WindowManager` (чистый): одно окно за раз, закрытие ✕ / мимо / `Esc`, `last` — последнее окно сессии (только в памяти). `openWindow({ id, title, body, buttons })`, `closeWindow`, `isWindowOpen`, `lastWindow`; `initWindows()` зовёт `ui.ts`. Кнопки содержимого — обычные `data-a`, их обрабатывает `ui.ts`. Первое окно — утреннее; склад и верстак (V2.3) — следующие.
- `src/actionbar.ts` — полоса действий (V1.5): `mainAction(state, actor, tab)` выбирает одну главную кнопку экрана (позвать, предложить, заплатить, спать…) или блёклую подсказку; `chipLines(state)` — строки чипа на сцене: сначала игровое время, потом очередь (`chipIsNight(state)` — за полночь время цветом `wear`). Чистые правила; `ui.ts` рисует полосу и убирает это действие из панели.
- `src/heatmeter.ts` — шкала розыска на левой стене сцены (и на свалке): сирена сверху, 10 делений (пустые — контур `line`, заполненные — `risk`), с 8 мигают сирена и верхнее деление. Чистая функция, рисует `scene`.
- `src/icons.ts` — пиксельные иконки интерфейса (☰, ✕ окна и замок закрытого режима): inline SVG из прямоугольников на сетке, рисуются 2×, цвет — `currentColor` из CSS. Не эмодзи и не символы шрифта.
- `src/audio.ts` — лофи и звуки свалки; `musicWanted`/`rememberMusic` и `sfxWanted`/`rememberSfx` — выбор игрока, `startSoundOnGesture` — старт на первом касании, `playSfx(name)` — эффект (молчит при «Звуки: выкл»), `setJunkAmbience(level)` — тиканье при «громко». Играет `ui.ts` по результату логики.
- `src/rng.ts` — случайность правил: тип `Rng` (`() => number`), `gameRng` (в игре — `Math.random`, читается при вызове, поэтому паритет и моки в тестах работают), сидируемый `mulberry32(seed)` для тестов и симуляций, хелперы `randomInt(rng, …)`, `randomBetween`, `pickRandom`, `randomSeed`.
- `src/util.ts` — math- и текстовые хелперы без игровой логики и без DOM.
- `src/palette.ts` — **все цвета игры**, единственное место с цветовыми литералами. С V1.7 (палитра A «Сталь и ржавчина») hex есть только в `BASE` — ровно 16 базовых цветов (`ink`, `bg`, `panel`, `wall`, `line`, `dim`, `fg`, `rustDark`, `rust`, `skin`, `action`, `wear`, `risk`, `hunch`, `ok`, `lamp`); все роли ниже ссылаются на них или на `withAlpha()` от них, новый hex не добавляем. Одежда клиентов — выбор из базовых по сиду (`CUSTOMER_TONES.jackets/shirts/trims`), без `hsl()`. Те же 16 цветов — `src/dark-counter-palette-A.gpl` для Piskel/Aseprite (тест сверяет). Роли: общие `COLOR`, группы по месту использования (`SHOP`, `JUNKYARD`, `CHARACTER`, `CUSTOMER_TONES`, `ITEM_COLORS`), полупрозрачные `SHADE`/`GLOW` через `withAlpha()`, `MEANING` — цветовой словарь поверх базовых цветов, `CSS_TOKENS` для CSS (включая `--m-*`). Имена базовых цветов — по месту в сцене или интерфейсе, смыслы (риск, польза) — только в `MEANING`. Чистые данные: импортируют и canvas, и Vitest, и `vite.config.ts`.
- `src/dom.ts` — `byId` и другие DOM-хелперы для `ui` и `scene`; `markIosPwa()` ставит класс `ios-pwa` на `<html>` в установленной iOS-PWA (полоса «потолок станции»).
- `src/diag.ts` — отладочный оверлей для бага с отступом в iOS-PWA: долгий тап по подписи версии в окне «сейв». Читает DOM сам, подключается в `main.ts`, сейв и игру не трогает.
- `src/fontlab.ts` — «лаборатория шрифтов», отладочная шторка: диагностика → «Шрифты». Меняет на лету `--fs-*` и шрифт групп (названия, цены, вердикт, числа HUD, заголовки) через `data-fl-*` на `<html>`, правила — в конце `style.css`. Знает профиль (телефон / десктоп) и DPR, у пиксельных размеров пишет «чётко / мягко». Хранится в `localStorage` по профилю: `dark-counter-fontlab` (телефон) и `dark-counter-fontlab-desktop`, не в сейве; «Скопировать» даёт итог для задачи с профилем в начале.
- `src/version.ts` — подпись версии в окне «сейв»: `__APP_VERSION__` (из `package.json`) и `__COMMIT_HASH__` (из git) подставляет Vite через `define` в `vite.config.ts`.
- `src/style.css` — стили; нецветовые токены (шрифты, `--pwa-ceiling`) в `:root`. Цветовые `--bg`, `--cyan`… вставляет в `<head>` `index.html` плагин `paletteCss` из `vite.config.ts` (и в dev, и в сборке). Формат: один селектор и одно свойство на строку.
- `public/icons/` — иконки PWA.
- `public/fonts/` — Public Pixel (`.woff2` и `.ttf` автора без изменений) и `README.md` с лицензией CC0 и источником.
- `tests/unit/` — Vitest: логика и сейв.
- `tests/fixtures/` — реальные коды сейвов прошлых версий.
- `tests/sim/` — бот баланса (`npm run sim`): стратегии `careful`/`owner` (откалибрована по плейтесту владельца)/`greedy` на чистых правилах и `mulberry32`; в `npm test` только смоук `tests/unit/sim.test.ts`.
- `tests/parity/` — стенд паритета: эталонная версия против кандидата в headless Chrome (см. его README). Гонять при рефакторинге и миграциях; если вид меняется намеренно — `PARITY_LOGIC_ONLY=1`.

Правило: логика получает `state` и `rng` параметрами, меняет `GameState` и возвращает результат; глобальный `state`, `ui`, `actor` и `Math.random` она не трогает. Глобальную игру держит `state.ts`, правила зовёт `ui.ts` с `state` и `gameRng`, а по результату сам переключает экран (`followGame`: ушедший клиент уходит со сцены, проданная вещь снимается с выбора). Например, `sleepUntilMorning(state, rng)` возвращает события ночи, а всплывающие числа кладутся в очередь `feedback`. DOM трогают только `ui.ts`, `scene.ts` и `window.ts` (через `dom.ts`). Без `any`; если тип неочевиден, описываем его в `types.ts`.
Импорты без циклов: `types`/`data`/`util`/`rng`/`palette`/`icons`/`heatmeter`/`day` → `appearance` → `profile` → `state` → `economy` → `actionbar` → `scene` → `window` → `ui` → `main`.

### Новый товар
1. Одна строка в `ITEM_TYPES` в `src/data.ts`. Тип `ItemType` выводится из ключей каталога, правка в `types.ts` не нужна.
2. Иконка (по желанию) — запись в `ITEM_SPRITES` в `src/scene.ts`. Без неё товар рисуется без иконки.
3. Если товар должен попадаться как редкая находка, добавить ключ в `RARE_FINDS`. Порядок в этом списке влияет на случайный выбор, поэтому вывести его из каталога пока нельзя.

## Сохранения: не ломать
- Ключи localStorage: `dark-counter-v3` — слот режима `story` (старые сейвы лежат здесь), `dark-counter-calm-v3` — слот `calm`, `dark-counter-profile` — профиль. Не менять без миграции. Настройки не в сейве: `dark-counter-music`, `dark-counter-sfx`.
- Поле `mode` в сейве выбирает слот; сейв или код без него — `story`. Импорт кода кладёт игру в слот её режима и переключает на него.
- Код сейва: `DC2:` + base64(deflate-raw(JSON)) через `CompressionStream`; без него — `DC1:` + base64(JSON). Старые коды `DC1:` должны загружаться всегда. В сейв и код идут только последние `SAVE_LOG_LINES` (10) строк ленты. В окне «Сохранение» — скачать код файлом и загрузить из файла.
- Поля `GameState` (`day`, `inv`, `cust`, `llAt`, у предметов `t`, `k` и т.д.) — это формат сейва. Короткие имена не переименовываем ради красоты, а описываем в `types.ts`.
- Новое поле в `GameState` → значение по умолчанию в `migrate()`. Переименование или удаление поля → преобразование в `migrate()`.
- В `tests/fixtures/` лежат реальные коды сейвов прошлых версий. Тест обязан загружать каждый из них.

## UI
- Mobile-first: iPhone в портрете. Вся игра помещается в один экран, прокручивается только нижняя панель (`.pane`).
- Учитывать safe-area (`env(safe-area-inset-*)`). Кнопки не меньше ~36px по высоте.
- Все цвета только из палитры `src/palette.ts`: в CSS через токены (`--bg`, `--panel`, `--cyan`, `--amber`, `--red`, `--green`…), в canvas через её объекты. Новый цвет — сначала в палитру. Тест `tests/unit/palette.test.ts` падает на `#rgb`/`#rrggbb`/`rgb(`/`hsl(` вне палитры.
- **Цветовой словарь: один цвет — один смысл.** Если цвет что-то сообщает игроку, он берётся из `MEANING` (TS) или `--m-*` (CSS) и классов `.m-*`, а не из базового `--red`/`COLOR.amber`:
  - `action` (бирюза) — действие, польза: главная кнопка, «чистый», доход;
  - `ok` (зелёный) — есть в наличии, готово (детали в сборке);
  - `risk` (красный) — краденое, ИИ, розыск, выселение, ошибка;
  - `wear` (оранжевый) — время, износ, дефект, терпение;
  - `unknown` (серый) — не проверено; всегда вместе со знаком «?», не только цветом;
  - `inactive` (блёклый серый) — нет в наличии, неактивно; никогда не красный;
  - `hunch` (фиолетовый) — Чуйка.
  Базовые акценты напрямую — только для декора (логотип, рамки, заголовки модалок). Список декора и проверки — `tests/unit/meaning.test.ts`.
- Шрифты: `--display` (Public Pixel) — заголовки, названия вещей, числа (кр., день, цены), вердикт Чуйки; `--mono` (IBM Plex Mono) — текст, описания, лог, реплики, кнопки, вкладки. Список пиксельных элементов — одно правило в конце `style.css`.
- Размеры только токенами из `:root`, литералов `px` в `font-size` вне `:root` нет (тест `tests/unit/fonts.test.ts`):
  - пиксельный — `--fs-px-s` 8px, `--fs-px-m` 16px, `--fs-px-l` 24px. Только кратные 8, иначе пиксели размываются; без жирного и без `letter-spacing`;
  - моно — `--fs-s` 12px (подписи, лог, метки HUD), `--fs-m` 14px (текст панелей, не меньше), `--fs-l` 18px.
  - Два профиля: **телефон** — `:root`, **десктоп** — `@media (min-width: 900px) { :root }` (тот же набор токенов, пока копия). Ширина совпадает с `DESKTOP_QUERY` в `src/fontlab.ts`, значения — с `PROFILE_SIZES` (тест `fontlab.test.ts`). Минимумы проверяются для телефона.
- Раскладка сверху вниз: «потолок станции» (iOS-PWA) → сцена (на телефоне во всю ширину, 160×100) → лента → вкладки → панель (прокрутка, занимает всё свободное) → **полоса действий** (`--bar-height`, одна главная кнопка ≥ 44 pt во всю ширину или подсказка `m-inactive`; кнопки на сцене нет) → **нижняя строка HUD** (`--hud-height`): кр · день/60 · платёж · зап с шагом 16px и ☰ 44×44 без плитки. Метки 11px (`--fs-xs`), числа — пиксельный 16px. Помещается на 375 pt. Пока открыта экранная клавиатура, нижняя строка скрыта (`kb-open`), а полоса действий остаётся над клавиатурой: игра сжимается до видимой части экрана (`--kb-height` из `visualViewport`). Розыск — шкалой на сцене, не в HUD. Стат платежа — кнопка: открывает окно долга (досрочный взнос, место на шаттле); оно же — пункт «Долг» в меню ☰. Новая игра — через «Режимы» в ☰.
- Облачко реплики и чип очереди не заходят на вывеску «ЛАВКА 7Б» (`SHOP_SIGN` в `data.ts`, тест `polish.test.ts`).
- Торг на 375×667 помещается в панель без прокрутки: карточка вещи компактная (факты осмотра — сами кнопки осмотра), бюджет высот в `polish.test.ts`.
- «Примерно N» — только через `approx()` в `ui.ts`: знак «~» набран моно (`.approx`), потому что Public Pixel рисует «~» как «∾», а его «≈» нечитаем.
- Без `alert`, `confirm`, `prompt`: только свои модалки.

## Релиз
1. `npm run typecheck && npm test && npm run build` — всё зелёное.
2. `npm run preview` в мобильной эмуляции. Чек-лист:
   - клиент входит и уходит;
   - сделка проходит;
   - Гробов приходит в день платежа, платёж уменьшает долг;
   - досрочный взнос, место на шаттле при нулевом долге, финал на день 60;
   - вечер и свалка работают;
   - сейв экспортируется и импортируется;
   - первый запуск показывает экран режимов, два режима играются независимо;
   - офлайн-запуск работает.
3. Работа в ветке → PR → мердж в `main` → Actions деплоит сам.
4. Коммиты по-русски, коротко: `торг: шанс согласия зависит от репутации`.

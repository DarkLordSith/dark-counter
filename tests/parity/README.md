# Стенд паритета поведения

Отвечает на вопрос: **ведёт ли себя новая версия игры точно так же, как эталонная?**
Нужен для рефакторинга и миграций, когда поведение меняться не должно.

Идея: в обеих версиях подменяем случайность и время одинаковыми детерминированными
заменами (`Math.random` с сидом, фейковые часы, ручной `requestAnimationFrame`).
Затем бот нажимает одни и те же кнопки в одном порядке. Если код эквивалентен,
после каждого шага всё должно совпасть до байта.

## Что проверяется

| Скрипт | Что делает |
|---|---|
| `diff.mjs` | Бот играет сотни шагов: торг, аренда, свалка, верстак, сейвы. Иногда он загружает подправленный сейв, чтобы дойти до выкупа, выселения и старого формата без `nextDue`. После каждого шага сравниваются сейв в localStorage, DOM, пиксели всех canvas, всплывающие числа. Периодически сравниваются вычисленные CSS-стили всех элементов, в первых трёх прогонах — ещё и скриншоты. |
| `savecompat.mjs` | Прогресс из эталона переносится в кандидата тремя путями: код `DC1:` (старый → новый), старый localStorage при загрузке страницы и код из нового в старый. После загрузки обе версии играют ещё 60 шагов и должны совпадать. |
| `audiotest.mjs` | Подменяет `AudioContext` записывающим фейком и сравнивает все вызовы Web Audio за ~35 секунд музыки. |
| `smoke.mjs` | Реальный браузер без подмен, экран iPhone, включённый service worker. Проверяет: нет скролла страницы, нет ошибок в консоли, игра запускается после перезагрузки офлайн. Сохраняет `out/mobile.png`. |
| `pixdiff.mjs` | Вспомогательный: показывает, чем отличаются два скриншота (`out/shotdiff.png`). |

## Запуск

Нужны Node 18+, Python 3 (раздаёт файлы) и Google Chrome. Chrome ищется в
стандартных путях macOS и Linux, свой путь задаётся через `CHROME=/path/to/chrome`.

```bash
# эталон — main, кандидат — текущая рабочая копия
tests/parity/run.sh

# эталон — любой коммит или ветка
tests/parity/run.sh 830dbcf

# кандидат — уже запущенная сборка (например, vite preview)
tests/parity/run.sh main http://localhost:4173/dark-counter/

# быстрее: меньше прогонов и шагов
RUNS=4 STEPS=150 tests/parity/run.sh
```

Если в новой версии намеренно появился элемент, исключите его из сравнения CSS-селектором.
Он будет скрыт и пропущен в обеих версиях:

```bash
PARITY_IGNORE='.new-thing' tests/parity/run.sh main http://localhost:4173/dark-counter/
```

Если вид меняется намеренно (новые цвета, классы, разметка), а логика и сейв — нет,
включите режим «только логика». Тогда сравниваются сейв, значения полей и пиксели canvas
(сцена и иконки), а разметка, стили, скриншоты и цвета всплывающих чисел — нет.
`savecompat` в этом режиме тоже сравнивает только сейв и сцену:

```bash
PARITY_LOGIC_ONLY=1 RUNS=4 STEPS=150 tests/parity/run.sh
```

Подпись версии в окне «сейв» (`.version`) исключается всегда. В ней хэш коммита, а он
у любых двух сборок разный. У эталона из `git archive` нет `.git`, поэтому там `dev`.

При первом запуске `run.sh` сам выполнит `npm install` в этой папке. Ставится только
`puppeteer-core`, он управляет установленным Chrome и не скачивает свой браузер.
В игру и на Pages эта зависимость не попадает.

Эталон берётся через `git archive <ref>`. Поэтому незакоммиченные изменения в эталон
не попадают, а в кандидата (рабочую копию) попадают.

Версия с Vite (в `package.json` есть скрипт `build`) собирается и запускается через
`vite preview`. Для эталона перед этим выполняется `npm ci` во временной папке, это
занимает около минуты. Старую версию без сборки (до миграции) стенд раздаёт как
обычные файлы, поэтому сравнивать можно с любым коммитом истории.

Скрипты можно запускать и по отдельности, если обе версии уже раздаются:

```bash
cd tests/parity
node diff.mjs http://localhost:8711/ http://localhost:8712/ 12 250
node savecompat.mjs http://localhost:8711/ http://localhost:8712/
node audiotest.mjs http://localhost:8711/ http://localhost:8712/
node smoke.mjs http://localhost:8712/
```

Полный прогон по умолчанию (12 × 250) идёт несколько минут.

## Как читать результат

- `identical` — прогон совпал полностью. В конце `run.sh` пишет `ПАРИТЕТ: OK`.
- `DIVERGED` — печатается первый шаг, где версии разошлись, что разошлось (`key`)
  и какое действие было последним. Значения `key`:
  - `save` — разное состояние игры. Это логика.
  - `app` или `modal` — разная разметка.
  - `canv` — разная картинка на canvas.
  - `styles` — разный CSS.
  - `shot` — скриншоты. Путь к картинкам печатается, сравнить их: `node pixdiff.mjs A.png B.png`.
- В `savecompat` `FAIL` означает одно из двух: сейв не загрузился или после загрузки
  версии стали играть по-разному.
- `actions exercised` показывает, сколько раз бот нажал каждую кнопку. Если нужной
  ветки там нет, увеличьте `RUNS` и `STEPS`.

## Ограничения

- Стенд сравнивает поведение, а не правильность: общий для обеих версий баг он не заметит.
- Он ловит только изменения, которые влияют на исход. Например, шанс покупателя
  0.45 → 0.46 меняет игру, лишь когда случайное число попадает в окно [0.45; 0.46).
  Это бывает редко, поэтому совпадение на нескольких сидах ничего не гарантирует
  для таких мелких сдвигов. Сдвиг 0.45 → 0.6 стенд ловит сразу (проверено).
- Важен порядок вызовов `Math.random`. Если код вызывает его в другом порядке
  (например, `RARE_FINDS` перестроен из каталога), стенд это покажет. Так и задумано:
  такие изменения делаются отдельно от рефакторинга.
- Шрифты грузятся с Google Fonts. Без сети скриншоты всё равно сравнимы между собой,
  но отрисуются запасными шрифтами.
- Стенд опирается на id и `data-a` из разметки (`#app`, `#offer`, `#savecode`,
  `data-a="call"` и т.д.). Если их переименовать, придётся поправить скрипты.
